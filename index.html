> STAGE SELECT

7 stages to review

Each stage feeds the next. Five AI passes run in parallel. Findings merged, deduplicated, ranked.

01

FETCH THE DIFF

Pull from a GitHub PR via gh or a local git diff range.

02

LOAD FEEDBACK MEMORY

Query SQLite store for previously dismissed findings. Inject as negative context so the agent avoids repeating patterns you've already rejected.

03

RUN STATIC ANALYSIS

Auto-detect linters & scanners (ruff, mypy, eslint, bandit, gitleaks, go vet, …) and run them over changed files. Deterministic signals injected as context.

04

RETRIEVE CROSS-FILE USAGES

Extract symbols from changed code, then ripgrep to find callers across the repo. Surfaces breakage risk a human reviewer might miss.

05

RUN 5 PASSES IN PARALLEL

Each pass focuses on one concern with a domain-specific prompt. All five run concurrently via ThreadPool.

SECURITY CORRECTNESS PERFORMANCE STYLE ARCHITECTURE
06

MERGE & DEDUPLICATE

Combine findings across all passes. Sort by severity. Drop duplicates found by multiple passes.

07

OUTPUT RESULTS

Terminal table for quick scanning, JSON for piping, or markdown for docs. Optionally post inline review comments to the GitHub PR.

> POWER-UPS

Built for real workflows

CLI for local dev. GitHub Actions for CI. Self-hosted server for teams. Memory that improves over time.

♦

MULTI-PASS REVIEW

Five specialized passes with focused prompts. Security, correctness, performance, style, architecture — each with domain-specific instructions.

♣

FEEDBACK MEMORY

Dismiss a finding once and it won't appear again. SQLite store tracks which findings humans reject — future reviews learn from your team.

♥

GITHUB INTEGRATION

Post findings as inline PR review comments. Critical issues request changes. Uses gh CLI — no API keys to manage.

♠

PLUGGABLE AGENTS

Use Claude Code, OpenCode, or Codex. Each has its own adapter. Choose per-review or configure as default.

○

STRUCTURED OUTPUT

JSON for piping to other tools. Markdown for docs. Terminal table for quick scanning. Every finding has severity, file, line, and suggestion.

▣

CI-NATIVE

Docker-based GitHub Action. Runs on every PR. Configurable passes and agents. Results posted directly to the PR.

◉

SERVER MODE

Run as a persistent GitHub App. Multiple repos install your app and get automatic reviews on every PR. Webhook-driven.

△

STATIC ANALYSIS PRE-PASS

Auto-detects linters and security scanners from your repo config. Runs them over changed files before the AI sees the diff.

□

CROSS-FILE USAGE RETRIEVAL

Extracts symbols from changed code, then ripgrep to find callers across the repository. Surfaces breakage risk.

▽

REASONING TRAIL

Each finding includes the agent's rationale. When humans dismiss a finding, the reasoning is persisted and fed back as context.

> BONUS STAGE

Self-hosted for teams

Run Superseded as a GitHub App on your own server. Multiple repos install it and get automatic reviews on every PR.

01

CREATE A GITHUB APP

Set up a GitHub App with webhook URL pointing to your server. Subscribe to PR and installation events.

02

INSTALL ON REPOS

Other repos install your app with one click. The server tracks installations automatically.

03

WEBHOOK TRIGGERS REVIEW

PR opened or updated — webhook arrives, job queued, review runs in background. Results posted as PR comments and status checks.

04

CONFIGURABLE CONCURRENCY

Control how many reviews run in parallel. Jobs queue when at capacity. Each review gets its own shallow clone and agent subprocess.

$ superseded serve --port 8000
Starting Superseded server on 0.0.0.0:8000
