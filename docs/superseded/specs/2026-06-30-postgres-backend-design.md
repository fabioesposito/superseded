# Postgres Backend for Server Mode Design

**Date:** 2026-06-30
**Status:** Approved
**Approach:** `Store` Protocol + new `PostgresStore`; `MemoryStore` (SQLite) left untouched

## Overview

Server mode (`superseded serve`) today persists all state — findings, feedback,
installations, review watermarks, learned rules, reflection state, review stats —
through `MemoryStore` in `memory/store.py`, which is hardwired to `aiosqlite` and a
single local file at `.superseded/memory.db`. That is fine for single-process local
runs but limits operators who want to run the server against a managed, durable,
multi-connection database.

This design adds optional Postgres support to **server mode only**, selected by a
single new `database_url` config field. The local CLI path (`review`, `feedback`,
`init`, etc.) is unchanged and keeps using the SQLite `MemoryStore` exactly as today.

## Goals

- Operators can point `superseded serve` at Postgres via one config field / env var.
- SQLite remains the default (zero-config, back-compat) and is still selectable.
- No behavioral change to the CLI path; `MemoryStore` class is untouched.
- Both backends expose the same surface so the server's worker/app/stats code is
  backend-agnostic.
- Existing `uv run pytest` stays green in environments without Postgres.

## Non-Goals

- A general-purpose ORM or query-builder layer.
- Schema migrations tooling (versioned migration files). Schema is auto-created.
- Supporting Postgres from the local CLI path. CLI stays on SQLite.
- Multi-tenant connection routing per installation (single DB, shared schema).
- Changing the SQLite schema or its on-disk format.

## Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Backend selection | `database_url` field on `ServerConfig`; scheme dispatches (`sqlite://`/empty → SQLite, `postgres(ql)://` → Postgres) | Single knob, URL is self-describing, matches common conventions |
| Abstraction shape | `typing.Protocol` named `Store` | `MemoryStore` satisfies it structurally with no class-hierarchy churn; keeps the stable CLI path literally untouched |
| Postgres driver | `asyncpg`, hard dependency in `[project.dependencies]` | Fastest async driver; matches how `aiosqlite` is already a hard dep; avoids optional-extra friction in the Action image |
| Schema management | Auto-create on boot (`CREATE TABLE IF NOT EXISTS`) | Matches the SQLite store's self-migrating ethos; no extra tooling |
| Connection strategy | Process-wide `asyncpg.create_pool()` sized to `max_concurrent_reviews + 2` | Reuses connections across reviews; headroom for webhook handler + stats |
| CLI scope | CLI path unchanged | User explicitly scoped this to server mode |

## Architecture

### File Layout (new + changed)

```
src/superseded/
  memory/
    store.py         # unchanged: MemoryStore / SQLite (CLI path)
    backend.py       # NEW: Store Protocol, make_store() factory
    postgres.py      # NEW: PostgresStore (asyncpg pool) + its SCHEMA + SQL
  audit/
    stats.py         # CHANGED: calls Store methods; no longer reaches into _db()
  server/
    config.py        # CHANGED: + database_url field + SUPERSEDED_DATABASE_URL env
    worker.py        # CHANGED: store type widened MemoryStore -> Store (TYPE_CHECKING)
    app.py           # CHANGED: same type widening
  cli.py             # CHANGED: `serve` builds store via make_store(config.database_url)
pyproject.toml       # CHANGED: + asyncpg to [project.dependencies]
```

### Component Responsibilities

- **`memory/backend.py`** — defines the `Store` Protocol (the contract the server
  consumes) and `make_store(database_url) -> Store`, which dispatches on URL scheme.
  No SQL here.
- **`memory/store.py`** — unchanged `MemoryStore` (SQLite). Gains two new methods
  (`get_review_stats`, `refresh_review_stats`) that move the SQL previously living
  in `StatsAggregator` into the store, so the SQLite and Postgres backends present
  the same surface. No other behavioral change.
- **`memory/postgres.py`** — new `PostgresStore` class implementing the `Store`
  Protocol against asyncpg. Owns its own schema constant and SQL (Postgres-native
  placeholders `$1..$n`, `GENERATED BY DEFAULT AS IDENTITY`, `ON CONFLICT`).
- **`audit/stats.py`** — `StatsAggregator` becomes a thin policy layer. Data access
  moves into store methods; the hint-building thresholds (dismiss/accept rates)
  stay here.
- **`server/config.py`** — `ServerConfig` gains `database_url: str | None = None`,
  populated from `SUPERSEDED_DATABASE_URL` (env) or top-level `database_url:` (YAML).
- **`server/worker.py`, `server/app.py`** — `store:` constructor params and
  annotations widen from `MemoryStore` to `Store` (a `TYPE_CHECKING` import keeps
  the Protocol out of runtime import cost). No runtime behavior change.
- **`cli.py` `serve`** — builds the store via `make_store(config.database_url)`
  (instead of `MemoryStore()` directly) and passes `max_size` through; the existing
  lifespan gains a `finally: await store.close()` so both backends release cleanly.

### Data Flow

```
superseded serve
  ↓
ServerConfig.from_env() / from_yaml()   →  config.database_url (str | None)
  ↓
make_store(config.database_url)          →  Store (MemoryStore | PostgresStore)
  ↓                                          (max_size = max_concurrent_reviews + 2)
worker = ReviewWorker(store=store, ...)
app    = create_app(store=store, ...)
  ↓
lifespan startup:
  await store.open()   # MemoryStore: opens sqlite conn + runs schema
                       # PostgresStore: creates asyncpg pool + runs schema
  ↓
(worker / webhook handlers call store.* methods; both backends behave identically)
  ↓
lifespan shutdown:
  await store.close()  # MemoryStore: close conn; PostgresStore: close pool
```

## The `Store` Protocol

Lives in `memory/backend.py`. Lists exactly the methods the server path consumes
today, plus the two stats methods pulled out of `StatsAggregator`:

```python
class Store(Protocol):
    # lifecycle
    async def open(self) -> None: ...
    async def close(self) -> None: ...
    async def init(self) -> None: ...

    # findings
    async def record_finding(
        self, finding_id: str, repo: str, pass_name: str, severity: str,
        file: str, line: int, title: str, description: str, reasoning: str = "",
    ) -> None: ...
    async def set_comment_id(self, finding_id: str, comment_id: int) -> None: ...
    async def get_finding_by_comment_id(self, comment_id: int) -> dict | None: ...
    async def record_feedback(self, finding_id: str, action: str) -> None: ...
    async def record_feedback_by_comment_id(self, comment_id: int, action: str) -> bool: ...
    async def get_dismissed_findings(self, repo: str) -> list[dict]: ...

    # installations
    async def record_installation(
        self, installation_id: int, owner: str, repos: list[str],
    ) -> None: ...
    async def get_installation(self, installation_id: int) -> dict | None: ...
    async def remove_installation(self, installation_id: int) -> None: ...

    # watermarks
    async def get_watermark(self, repo: str, pr_number: int) -> str | None: ...
    async def set_watermark(self, repo: str, pr_number: int, head_sha: str) -> None: ...

    # learning
    async def get_learned_rules(self, repo: str, limit: int = 5) -> list[dict]: ...
    async def get_reflection_state(self, repo: str) -> int: ...
    async def set_reflection_state(self, repo: str, last_feedback_id: int) -> None: ...

    # stats (moved out of StatsAggregator)
    async def refresh_review_stats(self, repo: str) -> None: ...
    async def get_review_stats(self, repo: str, min_sample: int) -> list[dict]: ...
```

`MemoryStore` already implements every method except the two stats methods; those
are added to it verbatim from the SQL currently in `StatsAggregator`. No other
change to `MemoryStore`.

## `make_store` Factory

```python
from urllib.parse import urlparse

def make_store(database_url: str | None, *, max_size: int | None = None) -> Store:
    if not database_url:
        return MemoryStore()                       # back-compat default
    parsed = urlparse(database_url)
    scheme = parsed.scheme
    if scheme in ("", "sqlite"):
        path = Path(parsed.path) if scheme == "sqlite" and parsed.path else DEFAULT_DB_PATH
        return MemoryStore(db_path=path)
    if scheme in ("postgres", "postgresql"):
        return PostgresStore(database_url, max_size=max_size)
    raise ValueError(f"Unsupported database scheme: {scheme!r}")
```

- `None` / empty → SQLite at the default path (current behavior, zero-config).
- `sqlite:///path/to.db` → SQLite at a chosen path.
- `postgres://...` / `postgresql://...` → `PostgresStore`.
- Anything else → `ValueError`, surfaced by `serve`'s existing
  `except ValueError` block (exit code 2 with a message).

`max_size` is threaded through from `serve` (`max_concurrent_reviews + 2`) and is
ignored by the SQLite path.

## PostgresStore

### Schema

Module constant `SCHEMA` in `memory/postgres.py`. Mirrors the SQLite tables with
Postgres-native types:

```sql
CREATE TABLE IF NOT EXISTS findings (
    id          TEXT PRIMARY KEY,
    repo        TEXT,
    pass        TEXT,
    severity    TEXT,
    file        TEXT,
    line        INTEGER,
    reasoning   TEXT NOT NULL DEFAULT '',
    title       TEXT,
    description TEXT,
    dismissed   BOOLEAN NOT NULL DEFAULT FALSE,
    comment_id  BIGINT,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE TABLE IF NOT EXISTS feedback (
    id          BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    finding_id  TEXT REFERENCES findings(id),
    action      TEXT,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE TABLE IF NOT EXISTS installations (
    id                  BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    app_installation_id BIGINT UNIQUE NOT NULL,
    owner               TEXT NOT NULL,
    repos               TEXT NOT NULL,
    created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE TABLE IF NOT EXISTS review_watermarks (
    repo        TEXT NOT NULL,
    pr_number   BIGINT NOT NULL,
    head_sha    TEXT NOT NULL,
    reviewed_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    PRIMARY KEY (repo, pr_number)
);
CREATE TABLE IF NOT EXISTS review_stats (
    repo         TEXT NOT NULL,
    pass         TEXT NOT NULL,
    severity     TEXT NOT NULL,
    file_pattern TEXT NOT NULL DEFAULT '*',
    total        BIGINT NOT NULL DEFAULT 0,
    accepted     BIGINT NOT NULL DEFAULT 0,
    dismissed    BIGINT NOT NULL DEFAULT 0,
    updated_at   TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    PRIMARY KEY (repo, pass, severity, file_pattern)
);
CREATE TABLE IF NOT EXISTS learned_rules (
    id              BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    repo            TEXT NOT NULL,
    rule_text       TEXT NOT NULL,
    evidence_count  BIGINT NOT NULL DEFAULT 0,
    confidence      DOUBLE PRECISION NOT NULL DEFAULT 1.0,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    last_applied_at TIMESTAMPTZ
);
CREATE TABLE IF NOT EXISTS reflection_state (
    repo               TEXT NOT NULL,
    last_feedback_id   BIGINT NOT NULL,
    last_reflection_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    PRIMARY KEY (repo)
);
```

Notes:
- `BIGINT` for any GitHub ID, PR number, or count (GitHub IDs exceed 2³¹).
- `TIMESTAMPTZ` (not bare `TIMESTAMP`) so multi-TZ deploys are unambiguous.
- `GENERATED BY DEFAULT AS IDENTITY` is the modern Postgres spelling of
  SQLite's `AUTOINCREMENT`.
- The two `ALTER TABLE` migrations the SQLite store runs (`comment_id`,
  `reasoning`) are baked into this schema from day one, so the Postgres path has
  no ALTER/`_migrate` step — `init()`/`open()` just runs `CREATE TABLE IF NOT
  EXISTS` for every table. A pre-existing hand-rolled Postgres schema is out of
  scope.

### Pooling & Lifecycle

- `PostgresStore.__init__(self, dsn: str, *, min_size: int = 1, max_size: int | None = None)`.
  `max_size` is stored, not resolved, at construction time.
- `open()`:
  - Idempotent guard on `self._pool is None`.
  - `self._pool = await asyncpg.create_pool(dsn=self._dsn, min_size=self._min_size,
    max_size=self._max_size, command_timeout=30)`.
  - Acquire one connection and run the full `SCHEMA` (`CREATE TABLE IF NOT
    EXISTS` per table).
  - Log `"Postgres pool opened (min=%d max=%d)"` and `"Postgres schema ensured"`
    at INFO via `logging.getLogger(__name__)`.
- `close()`: `await self._pool.close()`; set `self._pool = None`. Safe to call
  when already closed.
- `init()`: aliases `open()` for Postgres. (The SQLite store's distinction
  between `init()` and `open()` is about one-shot vs long-lived connections; a
  pool makes that distinction moot.)
- Every data method:
  ```python
  async with self._pool.acquire() as conn:
      await conn.execute("INSERT INTO findings ... VALUES ($1, $2, ...)", *args)
  ```
  Each method writes its own SQL with `$n` placeholders — no global regex
  adapter, since queries are short and few. asyncpg wants positional args
  unpacked (`*args`), not a single tuple.
- Return contracts: asyncpg `Record` rows are converted via `dict(row)` to match
  the existing `dict | list[dict]` shapes the worker/app consume.
- `PRAGMA journal_mode=WAL` and `os.chmod(..., 0o600)` are SQLite-only and
  skipped.

### SQL Portability Cheat-Sheet

| SQLite (today) | Postgres |
|---|---|
| `?` placeholders | `$1, $2, ...` |
| `INTEGER PRIMARY KEY AUTOINCREMENT` | `BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` |
| `INSERT OR REPLACE INTO t (...) VALUES (...)` | `INSERT INTO t (...) VALUES (...) ON CONFLICT (pk) DO UPDATE SET ...` |
| `PRAGMA journal_mode=WAL` | n/a (skip) |
| `CURRENT_TIMESTAMP` | `NOW()` (works with `TIMESTAMPTZ`) |
| `COUNT(*) FILTER (WHERE ...)` | identical syntax (works in both) |
| `aiosqlite.Row` (dict-like) | `dict(asyncpg.Record)` |
| `BOOLEAN` (SQLite treats as int) | native `BOOLEAN` |

The `INSERT OR REPLACE` in `record_installation` and `set_reflection_state`
becomes `ON CONFLICT ... DO UPDATE`. The `ON CONFLICT(id) DO UPDATE` in
`record_finding` and `set_watermark` already uses standard upsert syntax — only
the placeholder style changes.

## Config Changes (`server/config.py`)

- New Pydantic field on `ServerConfig`: `database_url: str | None = None`.
- `from_env`: read `SUPERSEDED_DATABASE_URL` (optional; absent or empty → `None`).
- `from_yaml`: accept top-level `database_url:` key (absent → `None`).
- No new validator. The URL is validated structurally by `make_store` (raises
  `ValueError` on unknown scheme), which `serve` lets propagate to its existing
  `except ValueError` block that exits 2 with a message. This keeps
  `ServerConfig.is_configured` / `require_configured` semantics unchanged — a
  server can be fully configured with `app_id`/`webhook_secret`/`private_key_path`
  and still default to SQLite, preserving back-compat.

## StatsAggregator Refactor

`audit/stats.py` currently reaches into `self._store._db()` and sets
`db.row_factory = aiosqlite.Row`, which couples it to aiosqlite and breaks the
moment the store isn't a `MemoryStore`.

**Move the two SQL queries into store methods:**
- `Store.get_review_stats(repo, min_sample) -> list[dict]` — the current
  `SELECT * FROM review_stats WHERE repo = ? AND total >= ?` query.
- `Store.refresh_review_stats(repo) -> None` — the current
  `INSERT INTO review_stats ... SELECT ... ON CONFLICT ... DO UPDATE` query
  (the `COUNT(*) FILTER (WHERE ...)` aggregate is identical syntax on Postgres).

`StatsAggregator`:
- `get_stats_context(repo)` calls `self._store.get_review_stats(repo,
  self.MIN_SAMPLE)` then runs the existing hint-building logic (dismiss-rate /
  accept-rate thresholds). Policy stays here; only data access moved.
- `_refresh(repo)` calls `self._store.refresh_review_stats(repo)`.
- `_classify_file_pattern` and `_CASE_EXPR` move into the store modules (each
  backend inlines its own copy of the CASE expression in its SQL). They were
  only ever used inside the SQL.

This makes `StatsAggregator` trivially fakeable in tests and removes its
private-API reach.

## CLI Wiring (`cli.py` `serve`)

Today `serve` constructs two `MemoryStore()` instances (one for the worker, one
for the app — pre-existing pattern). Replace both with a single
`make_store(config.database_url, max_size=config.max_concurrent_reviews + 2)`
call and pass that one store into both `ReviewWorker` and `create_app`. (Today
they don't share a connection object; both open their own. With a pool, sharing
one `PostgresStore` is correct — both draw from the same pool. The SQLite path
is unaffected because `MemoryStore` remains re-openable per the existing
contract.)

Lifespan change: add `try/finally: await store.close()` around the `yield` so
both backends release on shutdown. `MemoryStore.close()` is already a safe no-op
when nothing is open.

## Error Handling

- asyncpg raises `asyncpg.PostgresError` subclasses on query/connection failure.
  Methods let them propagate; the worker already wraps each review in a
  try/except that logs and continues — single-pass failures are non-fatal per
  AGENTS.md. No new error-translation layer.
- Pool exhaustion (`asyncpg.TooManyConnectionsError`,
  `asyncpg.ConnectionDoesNotExistError`): bubble up to the worker's per-job
  try/except; the job is skipped, the server stays up.
- `make_store` unknown scheme → `ValueError`, surfaced by `serve`'s existing
  `except ValueError` (exit 2).
- `open()` failure at boot (DB unreachable, auth failure): propagates out of
  lifespan startup → uvicorn logs the traceback and the process exits non-zero.
  Fail-fast-at-boot semantics; no retry/backoff (out of scope).

## Testing

The repo has no CI and no Docker test harness (AGENTS.md), so Postgres tests
must not break `uv run pytest` in a vanilla environment.

**Strategy: `@pytest.mark.postgres`, skipped unless `SUPERSEDED_POSTGRES_TEST_DSN`
is set.**

- `pyproject.toml`: register the marker
  (`[tool.pytest.ini_options] markers = ["postgres: requires a live Postgres
  (set SUPERSEDED_POSTGRES_TEST_DSN)"]`) and add
  `addopts = "-m 'not postgres'"` so the default run excludes them.
- New `tests/test_postgres_store.py`:
  - Module-level skip if `SUPERSEDED_POSTGRES_TEST_DSN` env var is absent.
  - Mirror the behavioral assertions from `test_memory_store.py` against
    `PostgresStore` — same contract, both backends.
  - Covers `record_finding` upsert, feedback recording, installation CRUD,
    watermark get/set, learned_rules, reflection_state, and the two stats
    methods.
- New `tests/test_memory_backend.py` (no live DB needed): assert `make_store`
  dispatches correctly for `None`, `""`, `"sqlite://"`,
  `"sqlite:///tmp/x.db"`, `"postgres://u:p@h/db"`, `"postgresql://..."`, and
  raises `ValueError` on `"mysql://..."`. Uses
  `unittest.mock.patch` to prevent `PostgresStore.__init__` from doing anything
  real.
- New `tests/test_server_config.py` cases: `database_url` from env, from YAML,
  default `None`.
- Extend `test_audit_stats.py`:
  - Rewrite the existing `_db()`-based assertions to call
    `store.get_review_stats` / `store.refresh_review_stats` instead (they were
    always reaching past the public API).
  - Assert `StatsAggregator.get_stats_context` produces identical output via
    the store method.
  - Add `MemoryStore.get_review_stats` / `refresh_review_stats` direct tests.
- `test_memory_store.py`, `test_memory.py`, `test_integration.py`,
  `test_server_*.py`: **unchanged.** They construct `MemoryStore` directly,
  not via `make_store`, and exercise the unchanged SQLite path.

Local Postgres workflow for developers:
```bash
export SUPERSEDED_POSTGRES_TEST_DSN="postgres://user:pass@localhost/superseded_test"
uv run pytest -m postgres -v
```

## Packaging

- `pyproject.toml`: add `"asyncpg>=0.30.0"` to `[project.dependencies]`
  (hard dep, per decision). `uv lock` / `uv sync` picks it up.
- The Action Dockerfile installs via `pip install .` and so picks up the new
  dep automatically (AGENTS.md). No Dockerfile change required.
- No new optional extra.

## Rollout / Back-Compat

- `database_url` defaults to `None` → SQLite → byte-for-byte today's behavior.
  Existing deployments see no change.
- `MemoryStore` class signature and behavior are unchanged; all existing tests
  pass without modification.
- The `Store` Protocol is purely additive (a new typing construct); existing
  `MemoryStore` references continue to type-check because `MemoryStore`
  satisfies `Store` structurally.
- The only externally observable change is the two new methods on
  `MemoryStore` (`get_review_stats`, `refresh_review_stats`), which are
  additive.

## Open Questions Resolved During Brainstorming

1. **Backend selection mechanism** → single `database_url` field; scheme
   dispatches. (Chosen over an explicit `backend:` selector or Postgres-only.)
2. **Scope** → server-only abstraction; CLI path unchanged. (Chosen over a full
   CLI+server refactor.)
3. **Driver** → `asyncpg`, hard dependency. (Chosen over psycopg v3 / optional
   extra.)
4. **Schema management** → auto-create on boot. (Chosen over versioned
   migrations.)
5. **Pooling** → process-wide pool sized to `max_concurrent_reviews + 2`.
   (Chosen over per-operation connections.)
