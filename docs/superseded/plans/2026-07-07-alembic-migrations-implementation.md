# Alembic Migrations Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the two hand-maintained `SCHEMA` constants (SQLite/Postgres) with SQLAlchemy models as the single source of truth, and run versioned Alembic migrations that auto-upgrade on every `store.open()` for both backends.

**Architecture:** SQLAlchemy declarative models in `memory/models.py` define the schema once. An async Alembic `env.py` (reusing `asyncpg`/`aiosqlite`, no new driver) runs DDL. A programmatic `alembic_runner` probes for pre-Alembic DBs, stamps them, then upgrades to head — called from each store's `open()` via `asyncio.to_thread` (so env.py's internal `asyncio.run` doesn't collide with the app event loop). Query code in both stores is untouched.

**Tech Stack:** Python 3.14, uv, SQLAlchemy 2.x (async), Alembic 1.13+, aiosqlite, asyncpg, pytest/pytest-asyncio, ruff, click.

**Spec:** `docs/superseded/specs/2026-07-07-alembic-migrations-design.md`

**Conventions (from AGENTS.md):**
- Every module starts with `from __future__ import annotations`.
- Invoke everything via `uv`: `uv run python`, `uv run pytest`, `uv run ruff`. System `python` may be 3.13 and will fail.
- Ruff rule set is strict (`E,W,F,I,N,UP,B,SIM,TCH,RUF`), line length 100, double quotes, isort with `known-first-party = ["superseded"]`.
- `except A, B:` is intentional — do not "fix" it.
- Never edit `uv.lock` by hand; change deps in `pyproject.toml` then `uv lock`/`uv sync`.
- Verify before done: `uv run ruff check src/ tests/` + `uv run ruff format src/ tests/` + `uv run pytest tests/ -v`.

**A note on the probe location (refinement within the approved design):** The spec's architecture section says the probe "rides the store's existing async connection." During planning this was simplified: the runner owns the probe too, using its *own* transient async engine (same `asyncpg`/`aiosqlite` drivers — the design's "no second driver" constraint is preserved). This keeps all migration logic in one place and makes each store's change a single delegation. The stores no longer probe; they just call `await asyncio.to_thread(runner.upgrade, url)`.

```python
    __tablename__ = "reflection_state"

    repo: Mapped[str] = mapped_column(String, primary_key=True)
    last_feedback_id: Mapped[int] = mapped_column(BigInteger, nullable=False)
    last_reflection_at: Mapped[str | None] = mapped_column(
        DateTime(timezone=True), server_default=func.now()
    )


class InstallationConfig(Base):
    __tablename__ = "installation_config"

    installation_id: Mapped[int] = mapped_column(
        BigInteger,
        ForeignKey("installations.id", ondelete="CASCADE"),
        primary_key=True,
    )
    key: Mapped[str] = mapped_column(String, primary_key=True)
    value: Mapped[str] = mapped_column(String, nullable=False)
```

Notes for the implementer:
- `pass` is a Python keyword, so the attribute is `pass_` with `mapped_column("pass", ...)`.
- `BigInteger` for all ids/counts/comment_id reconciles the SQLite-INTEGER vs Postgres-BIGINT drift (SQLite affinity makes this safe).
- `DateTime(timezone=True)` renders `TIMESTAMPTZ` on Postgres and `TIMESTAMP` on SQLite.
- `installation_config` declares the `ondelete="CASCADE"` FK; `0001` creates it on fresh DBs, `0002` retrofits it on existing Postgres DBs.

`src/superseded/memory/migrations/env.py`:

```python
"""Async Alembic environment.

Driven by the programmatic Config built in ``alembic_runner`` (runtime) or by
``alembic.ini`` (dev). The URL in the config is a SQLAlchemy async dialect URL
(``sqlite+aiosqlite:///...`` or ``postgresql+asyncpg://...``).
"""
from __future__ import annotations

import asyncio
from logging.config import fileConfig

from alembic import context
from sqlalchemy import pool
from sqlalchemy.engine import Connection
from sqlalchemy.ext.asyncio import async_engine_from_config

from superseded.memory.models import Base

config = context.config

if config.config_file_name is not None:
    fileConfig(config.config_file_name)

target_metadata = Base.metadata


def run_migrations_offline() -> None:
    url = config.get_main_option("sqlalchemy.url")
    context.configure(
        url=url,
        target_metadata=target_metadata,
        literal_binds=True,
        dialect_opts={"paramstyle": "named"},
        compare_type=True,
    )
    with context.begin_transaction():
        context.run_migrations()


def do_run_migrations(connection: Connection) -> None:
    context.configure(
        connection=connection,
        target_metadata=target_metadata,
        compare_type=True,
    )
    with context.begin_transaction():
        context.run_migrations()


async def run_async_migrations() -> None:
    connectable = async_engine_from_config(
        config.get_section(config.config_ini_section, {}),
        prefix="sqlalchemy.",
        poolclass=pool.NullPool,
    )
    async with connectable.connect() as connection:
        await connection.run_sync(do_run_migrations)
    await connectable.dispose()


def run_migrations_online() -> None:
    asyncio.run(run_async_migrations())


if context.is_offline_mode():
    run_migrations_offline()
else:
    run_migrations_online()
```

Notes for the implementer:
- `compare_type=True` lets autogenerate detect type changes (important for the drift guardrail in Task 9).
- `asyncio.run` inside `run_migrations_online` is why the runner calls us from a worker thread (Task 5).

```python
import pytest

from superseded.memory import alembic_runner


def _sqlite_url_for(path: Path) -> str:

def test_normalize_url_passes_sqlite_through():

def test_upgrade_fresh_db_creates_schema(tmp_path):
    db = tmp_path / "fresh.db"

    rev = alembic_runner.upgrade(_sqlite_url_for(db))

    assert rev == "0001"

    async def has_table(name: str) -> bool:
        async with aiosqlite.connect(db) as conn:
            cur = await conn.execute(
                "SELECT name FROM sqlite_master WHERE type='table' AND name=?", (name,)
            )
            return await cur.fetchone() is not None

    loop = asyncio.new_event_loop()
    try:
        assert loop.run_until_complete(has_table("findings"))
        assert loop.run_until_complete(has_table("alembic_version"))
        assert loop.run_until_complete(has_table("installation_config"))
    finally:
        loop.close()


def test_upgrade_pre_alembic_db_stamps_and_preserves_data(tmp_path):
```

```python
Public API:
- ``normalize_url(url)`` — convert superseded-style URLs to SQLAlchemy async
  dialect URLs.
- ``upgrade(url)`` — probe for pre-Alembic state, stamp if needed, upgrade to

from alembic import command
from alembic.config import Config
from alembic.runtime.migration import MigrationContext
from sqlalchemy.ext.asyncio import create_async_engine

_BASELINE_REVISION = "0001"


def normalize_url(url: str) -> str:
    """Convert a superseded-style DB URL to a SQLAlchemy async-dialect URL.

    - ``sqlite+aiosqlite://...``  -> unchanged
    - ``postgres://...``           -> ``postgresql+asyncpg://...``
    - ``postgresql://...``         -> ``postgresql+asyncpg://...``
    - ``postgresql+asyncpg://...`` -> unchanged
    """
    if url.startswith("postgres://"):
        return "postgresql+asyncpg://" + url[len("postgres://") :]
    if url.startswith("postgresql://"):
        return "postgresql+asyncpg://" + url[len("postgresql://") :]
    return url

    cfg = Config()
    cfg.set_main_option("script_location", str(files("superseded.memory.migrations")))
    cfg.set_main_option("sqlalchemy.url", url)
    return cfg

    """Return ``(has_alembic_version, has_findings)``.

    - ``has_alembic_version`` True  -> already an Alembic-managed DB.
    - ``has_findings``        True  -> DB has real schema tables.
    The caller decides stamp/fresh from the combination.
    """
    engine = create_async_engine(url)
    try:
        async with engine.connect() as conn:

            def _inspect(sync_conn):
                from sqlalchemy import inspect

                insp = inspect(sync_conn)
                return insp.has_table("alembic_version"), insp.has_table("findings")

            return await conn.run_sync(_inspect)
    finally:
        await engine.dispose()

        import asyncio as _aio

        # Replaced below — see note.
        pass
```

```python
"""add installation_config foreign key on postgres

Reconciliation for pre-Alembic Postgres databases: the legacy hand-written
Postgres SCHEMA lacked the ``installation_config -> installations`` foreign key
that the SQLite SCHEMA had and that the models now define. Fresh databases get
this FK in 0001; this migration adds it idempotently to existing Postgres DBs.

No-op on SQLite (cannot ALTER TABLE ADD CONSTRAINT; existing SQLite DBs keep
their pre-Alembic shape, as documented in 0001).

Revision ID: 0002
Revises: 0001
Create Date: 2026-07-07
"""
from __future__ import annotations

from typing import Sequence, Union

from alembic import op

revision: str = "0002"
down_revision: Union[str, None] = "0001"
branch_labels: Union[str, Sequence[str], None] = None
depends_on: Union[str, Sequence[str], None] = None


_CONSTRAINT_NAME = "installation_config_installation_id_fkey"


def upgrade() -> None:
    bind = op.get_bind()
    if bind.dialect.name != "postgresql":
        return

    existing = bind.execute(
        "SELECT 1 FROM pg_constraint WHERE conname = :name", {"name": _CONSTRAINT_NAME}
    ).scalar()
    if existing:
        return

    op.create_foreign_key(
        _CONSTRAINT_NAME,
        source_table="installation_config",
        referent_table="installations",
        local_cols=["installation_id"],
        remote_cols=["id"],
        ondelete="CASCADE",
    )


def downgrade() -> None:
    bind = op.get_bind()
    if bind.dialect.name != "postgresql":
        return
    op.drop_constraint(_CONSTRAINT_NAME, "installation_config", type_="foreignkey")
```
